# 居民站立回應與張望 — 2026-11-18

## 觀察與範圍

按規劃書 T017／T043／T066 及增加生活感動畫的要求，檢查既有角色圖集與世界繪製。一般居民原先固定使用正面站立圖，即使玩家靠近也沒有視覺回應。沿用圖集中已有的左右、背面正式 PNG，不以幾何圖形替代角色。

本輪對共用 character_sprite_art 的九種居民樣式加入站立時的視線回應。實際接入一般村民固定站位、三位關係居民固定站位及小栗種子攤；特殊獨立繪製的居民仍未涵蓋。不是十二居民全美術、全方向走路動畫或 NPC 尋路完成。

## 修改

- 玩家進入 72 個世界顯示像素（約 2.25 格）內時，居民轉向本機玩家，使用既有四方向角色圖。
- 遠處每十秒短暫左右張望，其餘時間保持原方向。九種樣式使用不同相位，避免整排同步。
- 重疊過近保持原朝向。減少動畫及拍照模式保持原姿勢。
- 明確由站立站點選用；玩家、船上同行者、坐姿及其他未選用的角色不受影響。不改地圖、角色座標、交談距離、物品、親密度、存檔或通訊。
- 此為客戶端生活感呈現，各客戶端面向自己的玩家，不代表共享伺服器 NPC 注意力或新的多人 AI。

## 實際驗證

Windows 原生 Godot 4.7.2／AMD OpenGL，獨立 QA 世界、1280×800。測試以預置站位與停止插值方式取樣，不宣稱人工走路試玩。capture_resident_idle.gd 最終 983 項、0 失敗：

- 九種樣式在完整時間週期的方向、四方向近距離優先、靜態模式及玩家排除。
- 原生實際居民區域：一般模式三種不同 PNG 畫面；減少動畫與拍照模式各一種。
- 四方向靠近的原生居民區域各不相同，留下完整圖及局部圖。
- 每次繪製前後完整世界資料相同；未搬移測試站位的過程中相機不變。測試站位切換會觸發原本快照重置相機，因此使用各次切換後的相機作基準，並未修改正式鏡頭程式。
- 使用原本 _interact 入口成功開啟居民對話。

character_sprite_art 93 項通過，原居民對話／送禮／關係事件 UI 11,437 項通過，含 1024×640、1280×800 及四級字體倍率。第一版驗證器誤用不存在的 PackedByteArray.sha256_buffer 已改用僅作畫面差異比較的內建 hash，沒有放寬遊戲規則。
