# 密碼房世界備份與還原演練 — 2026-11-18

## 規劃範圍

推進 T059／T080／T095 世界還原與搬遷前置。現有匯出工具僅接受帳號世界的名冊與身分資料庫，無法為純房間密碼的試玩服製作可驗證的匯出。新增明確的 export-world 模式，並為兩種匯出模式加入與遊戲相同的實際作業系統寫入鎖。

沒有存取、更改、下載或部署目前雲端世界。沒有排程、異地儲存或把本機還原等同正式遷移完成。

## 實作

- Windows CreateFileW 獨占開啟，Linux flock 排他非阻塞，匯出期間持有正式 WorldWriteGuard 的同名同類型鎖。運行中拒絕，過期鎖檔存在仍可正常匯出，不靠刪鎖檔判斷是否停服。
- 純世界清單使用格式 2、mode=world-only；只複製世界主檔與存在的兩代備份，不建立假身分資料庫，不包含密碼。任何 members.json* 都要求使用原帳號模式。
- 原帳號清單格式 1 保持相容；原有 SHA256、SQLite 與名冊世界一致性核對保留。兩種還原均拒絕覆蓋既有目錄，匯出中來源改變或驗證失敗時不發布最終目錄。
- 工具的可讀世界檢查不是完整 Godot SaveSchema 檢查，實際匯出程式啟動另行驗證。

## 真實程序演練

work/world-only-backup-qa/runtime_test.py 每次建立唯一隔離目錄，只啟停自己建立的程序／容器；不使用玩家存檔。create_world_backup_fixture.gd 預置兩個角色、257 鈴幣、阿榆故事第一段與起始木材，以正常 World 動作蓋共用箱、存三份木材、鋤地、播種蘿蔔，經正式存檔驗證後開始。這是 QA 預置，不宣稱玩家自然賺取或完整開荒。

實測執行目錄：work/world-only-backup-qa/run-f41af11118，verification.json passed=true。

1. 啟動正式公開 r22 Windows EXE headless 世界服，確認 SERVER_READY。工具拒絕匯出且不產出目錄，證明 Python 鎖與真正 DLL 鎖互斥。
2. 停止該 QA 程序後匯出、verify、還原。所有世界代檔案 SHA256 與停服原檔完全一致，原檔不被改寫。
3. 啟動正式 r22 Linux 匯出 ELF 的 Docker 世界服。另一個 Python 3.12 Linux 容器共用同一世界目錄，真正 Linux flock 拒絕在線匯出，不用 Windows 檔案鎖推論 Linux 行為。
4. 停止 Linux 世界服後，由 Linux 工具容器完成匯出、驗證、還原。代檔逐一雜湊相同；殘留 writer-lock 不妨礙備份。
5. 正式 Linux 匯出世界服從還原目錄啟動。Windows Godot 測試客戶端以真實 WebSocket、兩個獨立 MultiplayerAPI 原身份加入，14 項通過：原背包、257 鈴幣、個人故事、箱子及三木材、蘿蔔均在。實際請求蓋椅只扣 6 木材，原蘿蔔可澆水。
6. 停止容器並直接檢查磁碟，兩個原角色、箱內三木材、故事及新椅所有權和扣料正確。使用同還原目錄再開新容器，兩個原身份再次加入，10 項通過，椅子仍在。最初未還原的 Linux 來源檔案雜湊仍完全相同。

QA 容器已全部停止並移除，產物及日誌保留；未刪除其他既有 Godot 或 Docker 程序。

## 回歸

Windows Python 與 Linux Python 3.12 各 10 個 unittest 通過，涵蓋過期／持有鎖、原格式1相容、兩種還原拒絕覆蓋、損壞主檔可保留有效備份、全損壞拒絕、來源改變、摘要竄改、額外檔案、路徑逸出與模式混淆。實際的完整 SaveSchema、原身份連線與保存由上面的匯出伺服器演練補足，沒有只憑工具的 JSON 檢查宣布可玩。

## 限制與下一步

這是同一台 Windows 主機上的原生程序和 Docker Linux、loopback WS；不是跨電腦、公開 WSS 或正式 Zeabur／騰訊雲遷移。測試客戶端為目前 GDScript 測試程序，不宣稱手動 Windows 圖形 EXE 連線試玩。本輪沒有 UI 變更，沒有遊戲畫面截圖。新備份工具尚未納入已發布 r22 的不可變下載包，未改其協定或存檔格式。

正式目標仍包括雲端原資料盤點與停服備份、遠端私有傳輸、部署設定與憑證交接、異地儲存／復原時間量測及真正外部連線驗收。T059／T080／T095 不能以本輪局部演練全部結案。
