# 林業加工完工落架動畫 — 2026-11-18

## 對應規劃與基準

延續規劃書 T036 及使用者確認的「開始、運轉、完工、領取各有回饋」方向。前一目標回合完成釣魚等待動作及實機證據，屬於有進展。本輪先實際執行現行加工場景：鋸木與炭窯已有運轉、木屑、爐火、煙氣，完成後成品直接出現在架上，沒有出料過渡。修改前原生 36 項通過，畫面保留於 work/processing-finish-qa/before。

## 實作

新增 ProcessingFinishFeedback，僅觀察正式快照中鋸木台、炭窯的新完成批次或輸出緩衝新增物品。以既有批次 ID 判斷，不依賴待領數量增加，因此領走一批同時另一批完成時仍可辨識；active 到期投影與 ready 共用 ID，避免重複播放。舊 job 轉成正式佇列的既有完成品也不當成新產出。

成品原 PNG 在固定架上方最多七像素短暫落下、回彈後停穩，總長 0.65 秒。設備、架子、地面及鏡頭保持原位，不縮放或旋轉像素圖。重送不重播，初次加入、跨區、時間回退及斷線重連首份資料只作基準；最多保留 64 個短期顯示事件。減少動畫及拍照模式維持原靜態成品。

不改加工時間、材料、佇列、產量、背包、碰撞、存檔或網路欄位。沿用 protocol47；本輪未發布、不冒充已更新公開 r20。

## 驗證

- 回饋規則 43 項零失敗：初入、重送、同數量新批次、到期投影去重、舊資料轉換、自動緩衝、移除、時間回退、跨區、重設後首份、靜態模式、期限及儲存上限。
- Windows Godot4.7.2 原生一般、減少動畫、拍照模式各 94 項零失敗。預置設備、原料、角色站位，以 Session 真正排入兩批木板、兩批木炭並快轉加工，實際各領四份。不是真人從新開局採料建機器。
- 每模式拍 18 張完工幀；逐幀確認完整 World 資料與相機不變，伺服器時間暫停時客戶端動畫仍結束。像素比較顯示一般木板／木炭各六個不同狀態；低動態及拍照各一個。
- 原加工世界規則 1177、加工介面 871、Session 路由與公開資料 150、版本 39 項通過。Session 測試為既有記錄型測試替身，不是本輪真實 WebSocket 連線。
- 首次執行新錄影分支遇到 GDScript 無法推導穩定狀態變數型別，改為明確 Dictionary 後通過。原 Session 測試仍寫死協定45、錯誤訊息卻寫39，與現行47不符；改為檢查支援39及與當前 release.json 一致，最終150項通過。未降低正式程式的版本檢查。

## 畫面與限制

證據：work/processing-finish-qa/{after,reduced,photo} 原生圖及對應 .log，pixel-verified.json。outputs/processing-finish-motion/after.gif 是原生圖局部最近鄰四倍放大，50ms 對應測試逐幀推進的本機動畫時間，尾幀停留600ms供觀察；frames.png 依序為起始、落下中及落穩，未合成新動作。

視覺檢查：產物輪廓、架子和設備保持可辨識；動作幅度小，沒有遮擋角色或新增大型通知。原先重複的加工提示與過大的互動牌仍存在，本輪沒有視為解決。僅補完鋸木台與炭窯的完工階段，沒有宣稱領取飛入背包、所有加工設備或完整商業動畫已完成。未驗手機、跨裝置、Zeabur或匯出安裝版。
